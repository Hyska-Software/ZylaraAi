# Plugin packaging

Use `plugin_studio` for authoring, validation, signing, packing and installation.
The package is a ZIP with `manifest.json` at the root and a detached
`META-INF/signature.json`. The signature covers a canonical digest of files, not
raw ZIP bytes.

## `plugin_studio` actions

All calls are JSON objects with `action` required:

| Action | Required | Result |
|---|---|---|
| `init` | `pluginId` | creates folder, manifest template, locales/skill and studio key |
| `write` | `plugin`, `path`, `content` | writes UTF-8 or base64 file |
| `read` | `plugin`, `path` | text content (≤512 KiB); never signing material |
| `list` | `plugin` | files and sizes (≤400) |
| `remove` | `plugin`, `path` | removes one file |
| `validate` | `plugin` | `PluginPackageInspection` + valid/error markers |
| `pack` | `plugin` | signed `.zplugin`, canonical hash, file SHA-256 |
| `install` | `plugin` | stages the plugin disabled; returns id/version/permissions |
| `status` | `plugin` | paths, version, files, package state, key fingerprint |

Optional: `name`, `slug`, `target` (`auto`/`studio`/`workspace`), `template`
(`sandbox`/`declarative`/`trusted`), `encoding` (`utf8`/`base64`).

`target:"auto"` uses `<workspace>/plugins/<slug>` for a trusted Code workspace
and `<app-data>/plugin-studio/<conversation>/<slug>` otherwise. Chat always uses
the app-data studio. `target:"workspace"` without a trusted workspace fails;
`target:"studio"` always uses app data. `write`/`read`/`remove` reject
`META-INF/**`; the studio owns `publisher.key`, `publisher.pub` and
`studio.json`.

## Package layout

```
manifest.json
README.md
locales/{en,pt-BR,es}.json
ui/*.html
backend/index.html
main.js                 # trusted only
tools.json              # optional
prompt.md               # optional
skills/<name>/SKILL.md  # optional
assets/*
META-INF/signature.json # generated by pack
```

`META-INF/publisher.key`, `publisher.pub` and `studio.json` are never shipped.
Paths are relative, use `/`, max 240 chars, no `..`, absolute paths, drive
letters, ADS, symlinks or reserved Windows names. The package reader enforces
the generated byte/file/unpacked limits and rejects signing material, duplicate
case-insensitive paths and unsupported compression.

## Signature

`META-INF/signature.json`:

```json
{
  "schemaVersion": 1,
  "algorithm": "ed25519",
  "publisherId": "acme",
  "keyId": "studio-notes",
  "publicKey": "base64-32-byte-key",
  "signature": "base64-64-byte-signature",
  "packageHash": "sha256-canonical-digest",
  "signedAt": 1730000000000
}
```

The digest is `path\0sha256(file)\0` per file, sorted by path. The signature
covers the digest, not the ZIP timestamps. `signature.publisherId` must equal
`manifest.publisher.id`; `keyId` must match `publisher.keyId` when present. The
first install pins the publisher key; a later key change requires explicit
consent.

## Install and activation

- `plugin_studio install` calls the same manager path as `install_plugin` and
  stages the plugin **disabled** (`activation_required`). It never enables it or
  grants permissions.
- Do not install a plugin id that is already installed with a different version;
  use the update/rollback flow in Settings → Plugins instead.
- `validate_plugin` (Code only) validates a `.zplugin` or folder inside the
  workspace; `install_plugin` accepts a workspace path or HTTPS URL in Code and
  only an HTTPS URL in Chat. The studio is the preferred path when there is no
  workspace.
- After install, tell the user to review the plugin in Settings → Plugins and
  activate it. Trusted plugins also need trusted mode enabled and consent.

## Troubleshooting

| Error | Fix |
|---|---|
| `PLUGIN_INVALID` | Fix the manifest/UI/tool error named in the message; reload `plugin-manifest`/`plugin-ui` |
| `PLUGIN_UNSIGNED` | Use `plugin_studio pack` (always signed) or enable developer mode for local unsigned packages |
| `PLUGIN_ALREADY_INSTALLED` | Do not reinstall; update/uninstall in Settings → Plugins |
| `PLUGIN_VERSION_CONFLICT` | The installed version is newer; choose a different version policy |
| `signature publisher does not match` | Do not edit the publisher block created by init |
| `PLUGIN_STUDIO_WORKSPACE_UNAVAILABLE` | Use `target:"studio"` or open and trust a Code workspace |
| `PLUGIN_STUDIO_PATH` | Use a relative path inside the plugin folder; never `META-INF` |
| `PLUGIN_PERMISSION_DENIED` | Add the exact permission and reload the plugin |
| `PLUGIN_PACKAGE_*` | Fix the package/ZIP/manifest; do not bypass the reader |
| `PLUGIN_QUOTA_*` | Reduce files/size/result; the contract limit is final |

## Verification checklist

- `validate` succeeds; `pack` reports `packagePath`, `packageHash` and
  `packageFileSha256`; `install` reports `active:false`.
- The package has no signing material and no `.zplugin` inside the plugin
  directory.
- Every permission maps to a contribution; no feature is silently disabled.
- The user is told to review permissions and activate manually.
